# 第4章 核心概念与术语

## 4.1 LangGraph 核心概念

### 4.1.1 什么是 LangGraph

LangGraph 是 LangChain 生态系统中的一个框架，专门用于构建**复杂的有状态多智能体应用**。它基于图（Graph）的抽象，将业务流程建模为节点和边的集合。

**核心理念**:
- **状态驱动**: 应用状态是图的核心
- **节点执行**: 每个节点执行特定的处理逻辑
- **边连接**: 边定义节点间的执行顺序和条件
- **状态传递**: 节点间通过状态对象传递数据

### 4.1.2 StateGraph 工作流模型

ScholarFlow 使用 `StateGraph` 作为核心工作流模型：

```python
from langgraph.graph import StateGraph
from typing import TypedDict

# 定义状态类型
class WorkflowState(TypedDict):
    task_id: str
    status: str
    pdf_path: str
    chunks: List[str]
    results: List[dict]

# 创建图
workflow = StateGraph(WorkflowState)

# 添加节点
workflow.add_node("initialize", initialize_node)
workflow.add_node("process", process_node)

# 添加边
workflow.add_edge("initialize", "process")

# 编译
compiled = workflow.compile()
```

**关键特性**:
- **类型安全**: 使用 TypeScript 风格的 TypedDict
- **状态共享**: 所有节点共享同一个状态对象
- **状态更新**: 节点返回字典更新状态
- **类型检查**: 静态类型检查减少运行时错误

### 4.1.3 节点（Node）

**节点定义**:
```python
def node_function(state: WorkflowState) -> WorkflowState:
    """
    节点处理函数
    Args:
        state: 当前状态
    Returns:
        更新后的状态
    """
    # 处理逻辑
    result = process_data(state["data"])

    # 返回状态更新
    return {
        "status": "completed",
        "result": result,
        "updated_at": datetime.now().isoformat()
    }
```

**节点特点**:
- **纯函数**: 相同的输入总是产生相同的输出
- **无副作用**: 不修改输入状态，返回新状态
- **职责单一**: 每个节点只做一件事
- **可测试**: 易于单元测试

### 4.1.4 边（Edge）

**简单边**:
```python
workflow.add_edge("node_a", "node_b")  # A → B
```

**条件边**:
```python
def route_function(state: WorkflowState) -> str:
    if state["status"] == "success":
        return "success_node"
    elif state["status"] == "error":
        return "error_node"
    else:
        return "processing_node"

workflow.add_conditional_edges(
    "process_node",
    route_function,
    {
        "success": "success_node",
        "error": "error_node",
        "processing": "process_node"
    }
)
```

**循环边**:
```python
workflow.add_conditional_edges(
    "loop_node",
    should_continue,
    {
        "continue": "loop_node",  # 循环回到自己
        "exit": "exit_node"       # 退出循环
    }
)
```

### 4.1.5 检查点（Checkpoint）

**作用**:
- 在节点执行后自动保存状态
- 支持工作流暂停和恢复
- 提供状态版本管理
- 实现断点续传

**使用方式**:
```python
from langgraph.checkpoint.sqlite import SqliteSaver

# 创建检查点保存器
saver = SqliteSaver.from_conn_string("checkpoints.db")

# 编译工作流时传入
compiled = workflow.compile(checkpointer=saver)

# 执行时会自动保存状态
result = compiled.invoke(
    initial_state,
    config={"configurable": {"thread_id": "task_123"}}
)
```

**恢复工作流**:
```python
# 从检查点恢复
result = compiled.invoke(
    None,  # 不提供初始状态
    config={"configurable": {"thread_id": "task_123"}}
)
```

## 4.2 状态管理

### 4.2.1 WorkflowState 模型

ScholarFlow 的 `WorkflowState` 包含 30+ 个字段：

```python
class WorkflowState(TypedDict, total=False):
    # === 任务基本信息 ===
    task_id: str                          # 任务唯一标识
    status: str                          # 任务状态
    created_at: str                      # 创建时间
    updated_at: str                      # 更新时间

    # === 输入数据 ===
    pdf_path: str                        # PDF文件路径
    presentation_style: str              # 演示风格
    max_chars: int                       # 最大字符数
    target_chunks: int                   # 目标chunk数

    # === PDF解析结果 ===
    markdown_text: str                   # 原始Markdown
    image_paths: List[str]               # 图片路径列表
    tokenized_text: str                  # Token化后的文本
    image_token_map: dict                # 图片token映射
    token_count: int                     # token数量

    # === 文本分块 ===
    chunks: List[str]                    # 分块结果
    chunks_count: int                    # 分块数量

    # === Stage1 处理结果 ===
    stage1_results: List[dict]           # Stage1输出
    current_chunk_index: int             # 当前处理的chunk索引

    # === 合并结果 ===
    merged_outline: str                  # 合并后的大纲

    # === 人工审核 ===
    needs_human_review: bool             # 是否需要人工审核
    human_feedback: dict                 # 人工反馈
    review_points: List[str]             # 审核意见

    # === Stage2 处理结果 ===
    marp_markdown: str                   # Marp格式的Markdown

    # === 渲染结果 ===
    output_path: str                     # 输出文件路径
    output_format: str                   # 输出格式（pptx/pdf/html）

    # === 错误处理 ===
    error_message: str                   # 错误信息
    retry_count: int                     # 重试次数
    max_retries: int                     # 最大重试次数

    # === 进度跟踪 ===
    progress_percentage: int             # 完成百分比
    current_node: str                    # 当前节点
    execution_log: List[dict]            # 执行日志

    # === 元数据 ===
    version: str                         # 工作流版本
    metadata: dict                       # 额外元数据
```

### 4.2.2 状态流转

**正常流程**:
```
PENDING → PARSING → SPLITTING → STAGE1_PROCESSING
    ↓
MERGING → HUMAN_REVIEW → PROCESS_FEEDBACK
    ↓
STAGE2_PROCESSING → RENDERING → COMPLETED
```

**错误处理流程**:
```
任意节点 → ERROR → handle_error
    ↓
retry? → PARSING (重试) → END (失败)
```

**状态持久化**:
- **自动保存**: 每个节点执行后自动保存
- **版本控制**: SQLite 存储多个版本
- **快速访问**: JSON 存储最新快照

### 4.2.3 状态更新模式

**节点返回状态更新**:
```python
def node_process(state: WorkflowState) -> WorkflowState:
    # 读取状态
    data = state["input_data"]

    # 处理数据
    result = process(data)

    # 返回更新
    return {
        "status": "processing",
        "result": result,
        "progress_percentage": state.get("progress_percentage", 0) + 20
    }
```

**批量更新**:
```python
# 一次性更新多个字段
return {
    "status": "completed",
    "output": result,
    "progress_percentage": 100,
    "completed_at": datetime.now().isoformat()
}
```

## 4.3 Checkpointer 机制

### 4.3.1 什么是 Checkpointer

Checkpointer 是 LangGraph 的**状态持久化组件**，负责在节点执行后将状态保存到持久化存储，并在需要时恢复状态。

**核心功能**:
- 自动状态保存
- 状态版本管理
- 跨会话恢复
- 并发安全

### 4.3.2 SQLite Checkpoint 实现

**创建检查点**:
```python
from langgraph.checkpoint.sqlite import SqliteSaver

# 创建检查点保存器
saver = SqliteSaver.from_conn_string("checkpoints.db")

# 或使用文件路径
saver = SqliteSaver("checkpoints.db")
```

**保存状态**:
```python
# LangGraph 自动调用
config = {"configurable": {"thread_id": "task_123"}}
await saver.aget(config)
await saver.aput(config, {"channel": "my_channel", "value": state})
```

**恢复状态**:
```python
# 从检查点恢复
state = await saver.aget(config)
# state 包含完整的图状态
```

### 4.3.3 ScholarFlow 的双存储架构

ScholarFlow 采用 **SQLite + JSON** 的双存储方案：

**SQLite（LangGraph Checkpoint）**:
```python
# 优势：事务安全、版本控制、查询灵活
# 位置：data/workflows/checkpoints.db
# 用途：LangGraph 原生状态管理

class SqliteCheckpointer:
    async def save_state(self, task_id: str, state: dict):
        async with aiosqlite.connect(self.db_path) as db:
            await db.execute(
                "INSERT INTO checkpoints VALUES (?, ?, ?)",
                (task_id, json.dumps(state), datetime.now())
            )
            await db.commit()
```

**JSON（快速访问层）**:
```python
# 优势：人类可读、快速加载、无需查询
# 位置：data/workflows/intermediate/{task_id}/
# 用途：任务状态快速查询

class LocalStorage:
    async def save_snapshot(self, task_id: str, state: dict):
        path = Path(f"data/workflows/intermediate/{task_id}/{task_id}.json")
        async with aiofiles.open(path, 'w') as f:
            await f.write(json.dumps(state, indent=2))
```

**协同工作**:
```python
class WorkflowCheckpointer:
    def __init__(self):
        self.saver = SqliteSaver("checkpoints.db")  # LangGraph 原生
        self.local_storage = LocalStorage()         # 快速访问

    async def save_state(self, task_id: str, state: dict, node_name: str):
        # 保存到 SQLite（LangGraph 自动调用）
        # 保存到 JSON（手动调用）
        await self.local_storage.save_snapshot(task_id, state)

        # 记录执行日志
        log_entry = {
            "timestamp": datetime.now().isoformat(),
            "node": node_name,
            "status": state.get("status")
        }
        state.setdefault("execution_log", []).append(log_entry)
```

### 4.3.4 检查点策略

**保存时机**:
- 每个节点执行完成后
- 关键决策点前
- 错误发生前
- 人工审核暂停时

**保存内容**:
- 完整的工作流状态
- 执行历史记录
- 错误信息
- 进度百分比

**恢复策略**:
- 从 SQLite 恢复完整状态（用于工作流恢复）
- 从 JSON 加载快速状态（用于状态查询）
- 支持跨版本恢复

## 4.4 Token 化保护

### 4.4.1 问题背景

**问题**: LLM 在处理文本时经常修改图片路径，导致最终演示文稿显示破图。

**原因**:
- 图片路径通常是长哈希（如 `df31c4889a278a680daa11239dcc9df51b4c7fd8b86edfa336bc2b3dec9e25d0.jpg`）
- LLM 倾向于"优化"这些路径
- 复杂路径在 JSON/文本处理中易被破坏

### 4.4.2 Token 化方案

**三阶段保护**：

**Stage 1: Tokenize（PDF解析后）**
```python
# 将复杂图片路径替换为简单token

# 原始文本：
markdown = """
![Figure 1](images/df31c4889a278a680daa11239dcc9df51b4c7fd8b86edfa336bc2b3dec9e25d0.jpg)
"""

# Token化后：
tokenized = """
![Figure 1]([[TOKEN_IMG_001]])
"""

# Token映射：
token_map = {
    "[[TOKEN_IMG_001]]": {
        "hash": "df31c4889a278a680daa11239dcc9df51b4c7fd8b86edfa336bc2b3dec9e25d0",
        "alt_text": "Figure 1",
        "original_path": "images/df31c4889a278a680daa11239dcc9df51b4c7fd8b86edfa336bc2b3dec9e25d0.jpg"
    }
}
```

**Stage 2: Process（LLM处理时）**
- LLM 只看到简单 token：`[[TOKEN_IMG_001]]`
- 提示词明确禁止修改 token
- LLM 不会破坏图片引用

**Stage 3: Restore（渲染前）**
```python
# 将token恢复为正确路径

# 恢复后：
restored = """
![Figure 1](images/df31c4889a278a680daa11239dcc9df51b4c7fd8b86edfa336bc2b3dec9e25d0.jpg)
"""
```

### 4.4.3 实现细节

**Token 生成**:
```python
def generate_token(index: int) -> str:
    return f"[[TOKEN_IMG_{index:03d}]]"
```

**Token 化算法**:
```python
import re

def tokenize_images(markdown: str, task_id: str):
    token_map = {}
    token_index = 1

    # 匹配Markdown图片语法: ![alt](path)
    pattern = r'!\[(.*?)\]\((.*?)\)'

    def replace_with_token(match):
        nonlocal token_index
        alt_text = match.group(1)
        image_path = match.group(2)

        token = generate_token(token_index)
        token_index += 1

        token_map[token] = {
            "hash": extract_hash(image_path),
            "alt_text": alt_text,
            "original_path": image_path
        }

        return f"![{alt_text}]({token})"

    tokenized = re.sub(pattern, replace_with_token, markdown)
    return tokenized, token_map
```

**恢复算法**:
```python
def restore_tokens(tokenized_text: str, token_map: dict):
    def replace_token(match):
        token = match.group(0)  # 完整的token
        token_info = token_map.get(token)
        if token_info:
            return f"![{token_info['alt_text']}]({token_info['original_path']})"
        return token  # 如果找不到映射，保持原样

    # 匹配token模式
    pattern = r'\[\[TOKEN_IMG_\d{3}\]\]'
    restored = re.sub(pattern, replace_token, tokenized_text)
    return restored
```

### 4.4.4 优势

- ✅ **100% 图片完整性**: 永远不会出现破图
- ✅ **自动化**: 无需人工干预
- ✅ **可追溯**: token_map 记录所有图片元数据
- ✅ **可配置**: 支持自定义 token 格式
- ✅ **无副作用**: 不影响其他文本内容

## 4.5 关键术语表

### 4.5.1 工作流相关

| 术语 | 英文 | 定义 |
|------|------|------|
| **节点** | Node | 工作流中的单个处理单元 |
| **边** | Edge | 连接节点的路径，定义执行顺序 |
| **图** | Graph | 节点和边组成的结构 |
| **状态** | State | 工作流执行过程中的数据集合 |
| **检查点** | Checkpoint | 状态的持久化存储点 |
| **线程ID** | Thread ID | 工作流实例的唯一标识 |

### 4.5.2 处理流程相关

| 术语 | 英文 | 定义 |
|------|------|------|
| **Stage 1** | Stage 1 | 为每个文本块生成大纲的阶段 |
| **Stage 2** | Stage 2 | 将大纲转换为Marp Markdown的阶段 |
| **HITL** | Human-in-the-Loop | 人机协作审核机制 |
| **Chunk** | Chunk | 分块后的文本片段 |
| **Token** | Token | 图片的简化引用标记 |
| **Token化** | Tokenization | 将图片路径替换为token的过程 |

### 4.5.3 系统架构相关

| 术语 | 英文 | 定义 |
|------|------|------|
| **工作流引擎** | Workflow Engine | 负责编排和执行工作流的组件 |
| **状态机** | State Machine | 状态变化的抽象模型 |
| **条件路由** | Conditional Routing | 基于状态决定下一步执行的机制 |
| **并行处理** | Parallel Processing | 同时处理多个任务的能力 |
| **断点续传** | Resume from Checkpoint | 从保存点继续执行的能力 |

### 4.5.4 数据存储相关

| 术语 | 英文 | 定义 |
|------|------|------|
| **持久化** | Persistence | 将数据保存到持久化存储 |
| **快照** | Snapshot | 状态在某个时刻的完整副本 |
| **版本控制** | Version Control | 跟踪状态变化历史 |
| **事务** | Transaction | 原子性的数据库操作 |
| **ACID** | ACID | 原子性、一致性、隔离性、持久性 |
